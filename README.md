# [채용 과제] 제한된 용량의 고성능 데이터 저장소 구현

## 1. 개요 (Overview)
본 과제는 메모리 자원이 제한된 환경에서 데이터의 접근 패턴에 따라 효율적으로 데이터를 관리하는 일종의 스마트 캐싱 모듈을 구현하는 것입니다.

우리가 개발 중인 시스템은 매우 빈번한 데이터 조회와 쓰기 요청을 처리해야 합니다. 저장 공간이 가득 찼을 때, **가장 오랫동안 사용되지 않은(가치 낮음)** 데이터를 식별하여 제거하고 새로운 데이터를 저장하는 로직이 필요합니다.

이 과제를 통해 지원자의 **자료구조 설계 능력**, **알고리즘 최적화**, **코드 품질 및 가독성**, **구현의 이해**를 평가하고자 합니다.

---

## 2. 기능 명세 (Functional Requirements)

구현해야 할 클래스(또는 구조체)는 생성 시 고정된 크기(`capacity`)를 할당받으며, 다음의 동작 규칙을 엄격히 준수해야 합니다.

### A. 초기화 (Initialize)
* 저장 용량(capacity)에 해당하는 양의 정수를 입력받아 저장소를 초기화합니다.

### B. 데이터 조회: `get(key)`
* 저장소에 `key`에 해당하는 데이터가 존재하면 해당 `value`를 반환합니다.
* 데이터가 존재하지 않으면 `-1`을 반환합니다.
* **[중요]** 조회가 발생한 데이터는 **최근에 사용됨**으로 상태가 갱신되어야 합니다. 왜냐하면, 저장소 크기 제한으로 인해 데이터의 삭제시, 삭제 우선순위 판단에 사용되어야하기 때문입니다.

### C. 데이터 저장: `put(key, value)`
* 새로운 키-값 쌍을 저장합니다.
* **갱신:** 이미 키가 존재한다면 값을 업데이트하며, 이 경우에도 **최근에 사용됨**으로 상태가 갱신되도록 해야합니다.(데이터 조회시와 동일)
	* put 시점에 이미 동일한 `Key`가 존재하는 경우 overwrite 처리합니다. 
* **삽입 및 방출(Eviction):** 키가 없어서 새로 삽입해야 하는데 저장소가 가득 찬 경우, **가장 오랫동안 조회되거나 갱신되지 않은(Least Recently Used)** 데이터를 제거한 후 새 데이터를 삽입해야 합니다.


---

## 3. 기술 요구사항

### 1) 시간 복잡도 (Time Complexity)
* `get`과 `put` 연산은 호출 빈도가 매우 높습니다.
* 따라서 두 연산 모두 평균적으로 **$O(1)$ (상수 시간)** 내에 실행되도록 자료구조를 직접 설계하고 구현해야 합니다.

### 2) 사용 금지 라이브러리
* 내부 또는 외부 라이브러리 중 **이미 이러한 교체 알고리즘이 구현된 함수 또는 클래스**를 상속받거나 내부 래퍼(Wrapper)로 사용하는 것은 금지합니다.
* 기본적인 자료구조(Hash Map, List, Array, Pointer 등)를 조합하여 로직을 직접 구현해 주십시오.
* 기본적인 자료구조를 위한 내부 라이브러리는 사용해도 됩니다.

### 3) 프로그래밍 언어
* 반드시 C/C++ 언어를 사용해주십시오.

## 4. 동작 예시 (Scenario)

이해를 돕기 위해 용량(`capacity`)이 **4**인 저장소의 동작 과정을 C 언어 함수 호출 예시로 듭니다.
(*변수명은 `StorageCache`를 사용하며, 주석의 `최신순`은 왼쪽일수록 최근에 사용된 데이터입니다.*)

```c
// 1. 용량 4로 저장소 초기화
StorageCache* store = createCache(4);

// 2. 데이터 순차 저장
put(store, 1, 100);
// 현재 최신순: 1

put(store, 2, 200);
// 현재 최신순: 2 -> 1

put(store, 3, 300);
// 현재 최신순: 3 -> 2 -> 1

put(store, 4, 400); // 저장소 가득 참
// 현재 최신순: 4 -> 3 -> 2 -> 1 (가장 오른쪽 '1'이 삭제 후보)

// 3. 데이터 조회 (우선순위 변경 발생)
get(store, 1);      // 반환값: 100
                    // 1번을 조회했으므로 가장 최신 위치로 이동합니다.
                    // 현재 최신순: 1 -> 4 -> 3 -> 2 (이제 '2'가 삭제 후보)

// 4. 용량 초과 데이터 저장 (Eviction 발생)
put(store, 5, 500); // 새로운 Key 등장! 용량(4) 초과!
                    // 가장 뒤에 있는(오래된) 2번을 제거하고, 5번을 저장합니다.
                    // 현재 최신순: 5 -> 1 -> 4 -> 3

// 5. 삭제된 데이터 확인
get(store, 2);      // 반환값: -1 (찾을 수 없음)

// 6. 연속 저장 및 조회
put(store, 6, 600); // 용량 초과!
                    // 가장 뒤에 있는 3번을 제거하고, 6번을 저장합니다.
                    // 현재 최신순: 6 -> 5 -> 1 -> 4

get(store, 3);      // 반환값: -1 (제거됨)
get(store, 1);      // 반환값: 100 (아직 살아있음)
                    // 현재 최신순: 1 -> 6 -> 5 -> 4
get(store, 5);      // 반환값: 500
                    // 현재 최신순: 5 -> 1 -> 6 -> 4

// 7. 메모리 정리
freeCache(store);
